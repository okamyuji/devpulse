# テスト合格条件（agent-sessionsパネル実装）

出典は ~/devs/zenn/articles/ai-tests-coverage-blindspot.md の「AIにテストを任せるときの指示の出し方」8項目です。本プロジェクト（Rust、devpulse）の文脈へ具体化した次の各項目を、実装完了の受け入れ条件とします。

## T1. ケース種別の網羅

正常系、異常系、境界値、エッジケースをすべて用意します。異常系には不正入力だけでなく外部依存の失敗を含めます。本実装での外部依存の失敗とは、コマンド不在、コマンドのタイムアウト、部分失敗（4取得元の一部だけ失敗）、不正JSON、途中で切れた出力を指します。

## T2. 入力空間と組み合わせの点検

同値分割で入力空間を代表値に割り切ります。詳細設計6節の状態決定表は全行をデシジョンテーブルテストとして実装します。データ量は0件、1件、大量（1000件以上）の3水準を検査します。

## T3. 観点の列挙

時刻依存（quiet閾値ちょうど、閾値±1秒、未来時刻、不正な時刻文字列）、文字種（絵文字、サロゲートペア、日本語を含むタイトルとパス。実データのworkspaceタイトルに点字記号と日本語が実在する）、空文字とnullと巨大入力、権限（読み取り不能ファイル）、冪等性（同一入力で収集を2回実行して結果が同一であり重複統合が発生しないこと）をテスト観点として列挙し実装します。

## T4. 回帰テストの固定

本設計のレビューで実機検証により発見された次の実データ問題を、回帰テストとして固定します。

1. Kimiのagentsは配列ではなくオブジェクトで、main型の自分自身を含む
2. cmux eventsのsession_idとcwdはトップレベルではなくpayload内にのみ、一部イベントに限って存在する
3. cmux treeでtypeキーを持つのはsurfaceノードだけである
4. git rev-parse --git-common-dirの出力は呼び出し位置により相対と絶対が混在する
5. Kimiセッションはsessions直下ではなく2階層目にある（直下グロブは0件になる）
6. cmuxのlegacy aliasコマンドは通知行が出力へ混入する（正式形を使う）

## T5. アサーションの強度

アサーションは戻り値の中身と状態変化まで正しい値かどうかを確認します。エラーの有無だけ、Okかどうかだけの確認は合格にしません。

## T6. 並行性

unsafeコードを書かないこと（Rustの型システムによるデータレース排除を維持する）。背景収集タスクとスナップショット読み取りの並行動作は、反復実行テスト（同時読み書きを複数回繰り返し、パニックと不整合がないこと）で検査します。

## T7. モック境界の最小化

パーサのテストは実出力から採取したフィクスチャ（構造を保ったまま個人情報を一般化したもの）を使います。gitのテストはモックではなくtempfileで実リポジトリと実worktreeを作って検査します。psは実コマンドを実行して検査します。cmuxとclaudeのCLI実行テストは、コマンドが環境に存在する場合のみ実行し、存在しない場合はスキップしたことを明示します。

## T8. ミューテーションテスト

cargo-mutantsをsrc/data/agents/配下に対して実行し、スコアを記録します。判定は絶対値ではなく基準値からの悪化で行い、生き残った変異は個別に確認して記録します。初回実行の結果が基準値になります。

## 実行コマンド（受け入れの機械判定）

```
cargo build --all-targets
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo mutants --file 'src/data/agents/*' --no-times   # T8（初回は基準値の記録）
```
